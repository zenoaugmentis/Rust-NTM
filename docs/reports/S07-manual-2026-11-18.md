# S07 · Ручная сетевая проверка Minecraft 1.7.10

Автор: Zeno. Дата: 2026-11-18. [Задача #20](https://github.com/zenoaugmentis/horizon-NTM/issues/20).

Я запустил ванильный сервер 1.7.10. Из PowerShell проверил запрос статуса
с ping/pong и offline-вход с получением начальной позиции
и первых чанков. Сверил вывод зонда с консолью сервера и отдельно запустил
тесты S07.

## Стенд

Проверку я проводил на Windows. Сервер работал на `127.0.0.1:25567`
в offline-mode. Мир — плоский Overworld. Для запуска использовал сервер
из стенда [S01](../specs/versions.md), где зафиксирован SHA-1 JAR
`952438ac4e01b4d115c5fc38f891710c4941df29`. В этом прогоне я не выводил
хеш повторно, версии Java и Python отдельно не записывал. Для чтения
начального обмена зонд использует framing из [S04](../specs/protocol-5.md).

Для повторения опыта нужна отдельная копия сервера S01 с его конфигом Log4j.
В `server.properties` задать следующие параметры стенда.

```properties
server-ip=127.0.0.1
server-port=25567
online-mode=false
level-name=s07-flat
level-type=FLAT
level-seed=707
generate-structures=false
spawn-animals=false
spawn-monsters=false
spawn-npcs=false
view-distance=3
motd=Horizon S07 vanilla reference
```

Запуск из каталога сервера. При необходимости подставить путь к Java и имя JAR.

```powershell
java "-Dlog4j.configurationFile=log4j2_17-111.xml" -Xms256M -Xmx768M -jar ".\minecraft_server.1.7.10.jar" nogui
```

Команду зонда я выполнил из корня репозитория после запуска сервера.

```powershell
New-Item -ItemType Directory -Force .local/s07 | Out-Null; $report = ".local/s07/manual-$(Get-Date -Format yyyyMMdd-HHmmss-fff).json"; py -B tools/probe_s07.py --port 25567 --report $report; if ($LASTEXITCODE -eq 0) { Get-Content -LiteralPath $report }
```

## 1. Handshake и status

```text
TX id=0x00 frame=0f 00 05 09 31 32 37 2e 30 2e 30 2e 31 63 df 01
TX id=0x00 frame=01 00
RX id=0x00 body_length=122
TX id=0x01 frame=09 01 01 02 03 04 05 06 07 08
RX id=0x01 body_length=9
```

В первом handshake я отправил protocol `5`, адрес `127.0.0.1`, порт
`25567` (`63 df`) и next state `1`. В ответе сервер сообщил
`version.name=1.7.10`, `version.protocol=5`, `online=0`, `max=20`.
Pong повторил восемь отправленных байт `0102030405060708`.

## 2. Offline login и Join Game

```text
TX id=0x00 frame=0f 00 05 09 31 32 37 2e 30 2e 30 2e 31 63 df 02
TX id=0x00 frame=0a 00 08 53 30 37 50 72 6f 62 65
RX id=0x02 body_length=47
RX id=0x01 body_length=14
```

Во втором соединении я отправил handshake с next state `2` и
`Login Start` с именем `S07Probe`. Зонд проверил имя и offline UUID v3,
вычисленный из `OfflinePlayer:S07Probe`. В JSON получил
`offline_uuid_matches=true`.

В `Join Game` получились `entity_id=0`, `game_mode=0`, `dimension=0`,
`difficulty=1`, `max_players=20` и `level_type=flat`.
В консоли сервера я увидел вход с тем же entity ID и затем выход.

```text
[23:24:33] [Server thread/INFO]: S07Probe[/127.0.0.1:19464] logged in with entity id 0 at (589.5, 4.0, 1551.5)
[23:24:33] [Server thread/INFO]: S07Probe joined the game
[23:24:33] [Server thread/INFO]: S07Probe left the game
```

После завершения зонда
сервер записал `java.io.IOException: An existing connection was forcibly closed by the remote host`.
Сценарий штатного завершения сессии отдельно не проверял.

## 3. Начальная позиция

Зонд получил S→C пакет `0x08`, размер тела — 34 байта. В нём были
`yaw=0.0`, `pitch=0.0` и `on_ground=false`.

| Источник | X | Y | Z |
| --- | ---: | ---: | ---: |
| Пакет `0x08` | 589.5 | 5.620000004768372 | 1551.5 |
| Журнал входа на сервере | 589.5 | 4.0 | 1551.5 |

X и Z совпали. Разница между записанными значениями Y составила примерно
`1.62` блока. Проверял только начальную позицию после входа.

## 4. Первые чанки

Зонд получил S→C `Map Chunk Bulk` (`0x26`). В пакете было пять колонок
со skylight. Координаты ниже идут в порядке получения.

| X чанка | Z чанка | Основная маска | Add-маска | Байт после распаковки |
| ---: | ---: | --- | --- | ---: |
| 36 | 96 | `0x0001` | `0x0000` | 10 496 |
| 37 | 96 | `0x0001` | `0x0000` | 10 496 |
| 37 | 97 | `0x0001` | `0x0000` | 10 496 |
| 36 | 97 | `0x0001` | `0x0000` | 10 496 |
| 35 | 97 | `0x0001` | `0x0000` | 10 496 |

В каждой колонке была одна секция. Для неё получается
`4096 + 2048 + 2048 + 2048 = 10240` байт на ID блоков, metadata,
block light и sky light. Ещё 256 байт занимает массив биомов.
Сумма по пяти колонкам — `5 × 10496 = 52480` байт. Размер тела фрейма
тоже совпал с выводом зонда. Это 1 байт ID, 7 байт заголовка, 167 байт zlib
и `5 × 12` байт описаний колонок, всего 235 байт.

У всех пяти колонок получился один SHA-256 распакованного содержимого.

`80cdec8ce1a50778825cb103ef55f59361137f4cf2b4fd83433943d656388d09`.
Он совпадает и с [отдельным эталонным прогоном](evidence/S07/vanilla-flat.json).
В моём JSON `chunk_single=null`, поскольку в этом прогоне зафиксирован
bulk-пакет. Последняя строка вывода зонда приведена ниже.

```text
PASS: protocol 5 status/pong, offline login, position and bulk chunks
```

## 5. Проверка скрипта

В том же PowerShell я отдельно запустил тесты S07.

```powershell
py -B -m unittest discover -s tests -p "test_s07_*.py" -v
```

```text
test_bulk_rejects_invalid_bitmap_and_zlib_boundary ... ok
test_bulk_slices_columns_using_sky_and_add_masks ... ok
test_position_uses_absolute_doubles_floats_and_grounded_byte ... ok
test_single_partial_and_unload ... ok

Ran 4 tests in 0.003s
OK
```

Эти четыре теста проверяют Python-зонд на синтетических данных. Они
покрывают позицию, границы zlib, маски секций при распаковке bulk и
одиночный пакет `0x21`, включая вариант выгрузки чанка.

## Итог и границы

На моём стенде подтверждены handshake, status/pong, offline login,
начальная позиция и bulk chunks. Для N01 из опыта можно взять фреймы
handshake и ожидаемый результат status/pong, для N02 — проверку offline UUID
и перехода в Play, для N03 — поля позиции, размеры и хеши колонок.
При повторении на другом мире координаты спавна и набор колонок могут
отличаться.

Online-аутентификацию, движение и работу клиента Horizon в этом прогоне
я не проверял. В отчёт включены выбранные поля и фрагменты вывода.
Сетевые дампы, JAR, assets, сохранения и приватные токены не публикуются.
CI и code review остаются условиями закрытия [#20](https://github.com/zenoaugmentis/horizon-NTM/issues/20).
