# S11 · Матрица совместимости Minecraft 1.7.10

Задача [#24](https://github.com/zenoaugmentis/Rust-NTM/issues/24). Объём проверок определён по [дорожной карте](TEAM_ROADMAP.md) и [backlog](../planning/backlog.json). База аудита — ветка `Zeno-patch-reserve`, коммит [`ea4e87b54cdcbf2a40908fbfca129bb7c4a26d5a`](https://github.com/zenoaugmentis/Rust-NTM/commit/ea4e87b54cdcbf2a40908fbfca129bb7c4a26d5a).

## Статусы и критерий завершения

- **PASS** — воспроизводимый прогон выполнил обязательный критерий на указанной версии. Для совместимости 1.7.10 результат Rust сверяется с указанным эталоном.
- **FAIL** — прогон показал расхождение с критерием.
- **UNKNOWN** — отсутствует эталон, согласованная метрика, доступная реализация или результат пригодного прогона. Пропуск теста сохраняет `UNKNOWN` по той части, которую он проверяет.

Для приёмки milestone каждый обязательный сценарий из его строки должен получить `PASS`. В свидетельстве указываются ревизия, версия эталона, входные данные, команда или ручные шаги, ожидаемый и фактический результаты. Для повторяемого сравнения фиксируются seed и настройки, если они влияют на опыт. Для сравнений с допуском численное значение и способ измерения фиксируются до прогона. Статус ниже относится к приёмке всего milestone. Частичные результаты перечислены в колонке «Данные».

Готовность ванильной 1.7.10 в объёме дорожной карты определяется выполнением M0–M5. Локальная демонстрация требует проверок мира, рендера и игрового цикла M2–M4. Поддержка Native Mod API требует M6. Совместимость с каждым из трёх заявленных модовых прототипов подтверждается отдельно в M7–M9. Объём проверки прототипа ограничен сценарием в его строке.

## Прогон S11

Ручной прогон Zeno на Windows, Python 3.14.7. Ревизия приведена в начале документа. Команды из корня репозитория.

```powershell
git rev-parse HEAD; git status --short --branch
git ls-files -- Cargo.toml .github/workflows docs planning/backlog.json tools tests
$s11Ref = Join-Path $env:USERPROFILE 'Documents\horizon-reference'; @('versions\1.7.10\1.7.10.jar','server-vanilla\minecraft_server.1.7.10.jar','libraries\net\minecraftforge\forge\1.7.10-10.13.4.1614-1.7.10\forge-1.7.10-10.13.4.1614-1.7.10.jar') | ForEach-Object { Get-FileHash -LiteralPath (Join-Path $s11Ref $_) -Algorithm SHA1 }
py --version; py -B -m unittest discover -s tests -p 'test_*.py'; "TEST_EXIT=$LASTEXITCODE"
```

| Файл | Полученный SHA-1 | Сверка с S01 |
| --- | --- | --- |
| Клиент Java 1.7.10 | `e80d9b3bf5085002218d4be59e668bac718abbc6` | PASS |
| Сервер Java 1.7.10 | `952438ac4e01b4d115c5fc38f891710c4941df29` | PASS |
| Forge universal 10.13.4.1614 | `25fd97f72beca728112256938e03e8105b1b78cc` | PASS |

```text
Python 3.14.7
Ran 85 tests in 1.639s
OK (skipped=2)
TEST_EXIT=0
```

83 теста прошли. Два [теста модели шифрования](../tests/test_s04_crypto.py) помечены `skipUnless(CRYPTO)`; на этом стенде импорт необязательной зависимости `cryptography` был недоступен. При повторении с установленной зависимостью модель можно проверить командой `py -B -m unittest discover -s tests -p 'test_s04_crypto.py' -v`. Успешный online-login требует отдельного живого прогона.

Для S11 использованы результаты предыдущих игровых прогонов и проверены локальные JAR и инструменты. Сопоставимые прогоны Rust и регрессия 26.3 имеют статус `UNKNOWN`. Состояние CI и code review относится к PR S11.
